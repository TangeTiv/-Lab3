这个 TINY 编译器和解释器是一个非常经典的教学用编译器，它基于 Kenneth C. Louden 编写的《Compiler Construction: Principles and Practice》一书实现。

它的实现过程严格遵循了现代编译器的经典流水线架构：**词法分析 \-\> 语法分析 \-\> 语义分析 \-\> 代码生成 \-\> 虚拟机解释执行**。

以下是这个过程是如何实现的，以及各个文件在其中扮演的具体角色：

### **1\. 核心定义与整体驱动 (Core & Driver)**

* **GLOBALS.H (全局头文件)**：这是整个编译器的核心数据结构定义处。它定义了所有的标记类型（Token，如 IF, THEN, NUM, ID 等），并定义了抽象语法树（AST, Abstract Syntax Tree）的节点结构 TreeNode。整个编译过程都是围绕着这棵树进行的。  
* **MAIN.C (主程序)**：编译器的入口。它按顺序依次调用扫描器、解析器、语义分析器和代码生成器。  
* **UTIL.C / UTIL.H (辅助工具)**：包含用于构建抽象语法树节点（如 newStmtNode 和 newExpNode）以及在屏幕上打印格式化语法树的辅助函数。

### **2\. 第一阶段：词法分析 (Lexical Analysis)**

* **SCAN.C / SCAN.H (扫描器)**：它的作用是读取源文件（如 SAMPLE.TNY）中的每一个字符，跳过注释和空格，并将字符组合成有意义的词法单元（Tokens）。它实现了一个简单的有限状态机（DFA），核心函数是 getToken()，每次调用都会返回下一个识别出的 Token（例如将字符 := 识别为 ASSIGN）。

### **3\. 第二阶段：语法分析 (Syntax Analysis)**

* **PARSE.C / PARSE.H (解析器)**：这是编译器的前端核心。它通过调用扫描器的 getToken() 获取 Token 流，并使用**递归下降（Recursive Descent）算法来分析语法结构。它的核心功能是将线性的代码转化为内存中的抽象语法树（AST）**。比如，遇到 if 语句时，它会生成一个 IfK 节点，并为其挂载测试条件分支和执行体分支。

### **4\. 第三阶段：语义分析 (Semantic Analysis)**

* **SYMTAB.C / SYMTAB.H (符号表)**：实现了一个基于链表法解决冲突的哈希表（Hash Table）。它用于记录代码中出现的变量名、它们在内存中的分配位置，以及它们在源代码中出现的行号。  
* **ANALYZE.C / ANALYZE.H (分析器)**：遍历抽象语法树，进行语义检查。它主要做两件事：  
  1. **建立符号表** (buildSymtab)：记录所有变量的声明和引用。  
  2. **类型检查** (typeCheck)：确保运算合法（例如，确保加减乘除的左右节点都是整数类型 Integer，if 或 repeat 的条件判定部分是布尔类型 Boolean 等）。

### **5\. 第四阶段：代码生成 (Code Generation)**

* **CGEN.C / CGEN.H (代码生成器)**：它负责再次遍历已经经过语义检查的语法树，为每个节点生成对应的底层机器指令（针对 TM 虚拟机）。比如针对算术表达式生成 ADD, SUB 等指令，针对 if 和 repeat 生成条件跳转指令（Jump）。  
* **CODE.C / CODE.H (代码输出工具)**：提供了向文件输出 TM 汇编指令的底层函数（如 emitRO 发射寄存器指令，emitRM 发射内存指令，emitSkip 用于回填跳转地址等）。最终将结果写入 .tm 文件。

### **6\. 最终执行阶段：虚拟机 (Virtual Machine)**

* **TM.C (Tiny Machine)**：这是一个模拟的计算机硬件环境（解释器）。因为 TINY 语言并没有直接编译成 x86 或 ARM 这种真实的机器码，而是编译成了一种自定义的、简单的 TM 汇编语言。  
  * TM.C 内部模拟了寄存器（reg\[NO\_REGS\]）、指令内存（iMem）和数据内存（dMem）。  
  * 它的工作方式是读取你上一步编译出的 .tm 文件加载到内存中，然后利用 stepTM() 函数进入一个“取指-执行 (Fetch-Execute)”的死循环，逐条解释执行指令，直到遇到 HALT 停机指令为止。
